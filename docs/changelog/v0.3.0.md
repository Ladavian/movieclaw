## movieclaw v0.3.0

更新体验与整理输出能力升级。

### 新增

- **多版本回退选择器**：本地保留最近 N 个应用版本（默认 5，可调 2~20，磁盘占用外显），回退时逐项标明数据兼容性——未跨数据库迁移直接切换、跨迁移自动恢复对应时点备份（明示数据损失范围）、无备份时强警告；回退前自动做保险备份，回退本身也可撤销
- **监听导入「自定义目录」目标**：监听导入的整理输出不再绑定媒体库，可指向任意目录（网盘挂载、strm 生成目录等），订阅投递同步支持
- **「GitHub 更新」代理开关**：应用内更新的全部流量（检查、下载清单与产物、模型更新）纳入「设置 → 网络与代理」统一管理，新增服务开关与一键连通性测试，默认走代理

### 改进

- **更新提醒徽标化**：发现新版本不再进「待处理事项」打扰，改为侧栏常驻蓝色徽标入口，装完新版自动熄灭
- **「设置 → 应用」页重构**：分「版本与更新 / 网络与维护」双标签，进页即展示新版本卡片与更新日志（无需手动点检查）
- **待处理事项弹窗**：卡片化布局重构，主次操作分层更清晰

### 修复

- 自定义目录目标自查修复三处缺陷与体验问题
- 订阅投递活动记录补充暂存路径字段；CLI 基线 spec 重导出
- 应用更新接口 operationId 规范化，CLI 对应命令由 `app update_xxx` 变为 `app update xxx` 子命令

### 说明

- 发版流水线统一：应用 Release 发布后自动构建并推送多架构 Docker 镜像到 Docker Hub（movieclaw/movieclaw）
- 运行时依赖无变化（runtime=1），现有镜像可直接在「设置 → 应用」内一键更新到本版本
- 曾依赖环境变量代理更新流量的部署，升级后请在「设置 → 网络与代理」中开启「GitHub 更新」开关
